What we fixed or confirmed
The app classes are in src/, and the require_once paths resolve correctly from public/index.php, for example:

Diagnostic checks reported true for both is_file() and is_readable() for all four app files.

Several app files initially had text or blank content before <?php, which caused the strict_types errors. Moving <?php to the first line and declare(strict_types=1); to the second line fixed the syntax errors.

Query parameters reach PHP correctly. Visiting:

    Visiting http://localhost currently reaches the dispatcher with empty app and action, which leads to “Unknown app.” The dispatcher needs to render the landing page when app is empty.

    The dispatcher should allow page, create, read, update, and delete as appropriate, and handle an empty app as the landing page.

Suggested dispatch shape

Adapt this to the actual code in BirdApp.php:
$app = strtolower($_GET['app'] ?? '');
$action = strtolower($_GET['action'] ?? '');

$classes = [
    'duck' => DuckApp::class,
    'chicken' => ChickenApp::class,
    'goose' => GooseApp::class,
    'turkey' => TurkeyApp::class,
];

if ($app === '') {
    // Render the top-level landing page.
} elseif (!isset($classes[$app])) {
    http_response_code(404);
    echo 'Unknown app';
} else {
    $instance = new $classes[$app]();
    $action = $action ?: 'page';

    if (!in_array($action, ['page', 'create', 'read', 'update', 'delete'], true)
        || !method_exists($instance, $action)) {
        http_response_code(404);
        echo 'Unknown action';
    } else {
        // If the method prints its response:
        $instance->$action();

        // If it returns text instead, use:
        // echo $instance->$action();
    }
}
